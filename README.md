# InterviewIQ Backend

## Code map

The backend keeps HTTP orchestration in `main.py` and puts domain behavior in
focused services:

| Area | Files |
| --- | --- |
| Authentication and account security | `auth.py`, `services_auth.py`, `account_service.py` |
| Resume/JD analysis | `services.py` |
| Question generation | `question_service.py` |
| Interview lifecycle | `interview_service.py`, `interview_summary_service.py` |
| Voice metrics and pronunciation jobs | `voice_analysis_service.py`, `audio_analysis_queue.py`, `pronunciation_worker.py` |
| Personalized coaching assistant | `assistant_service.py`, `assistant_messages` |
| Persistence | `models.py`, `schemas.py`, `database.py` |
| Browser workspace | `static/app.*` |
| Live interview room | `static/interview.*` |

Use `/` for the authenticated workspace. `/interview` is the focused live
interview room, while `/docs` remains available for API-level testing.

InterviewIQ is a FastAPI backend that lets a user create an account, upload a
PDF resume, paste a job description, get AI feedback on how well the two match,
and generate interview questions.

## Features

* **Accounts:** register, log in and log out. Passwords are hashed with Argon2id. The login
  token is a JWT kept in an HttpOnly cookie. Logging out cancels the token on the server
  (via Redis), so a copied cookie stops working immediately.
* **Version history:** every resume and job description is saved as a numbered version and
  fingerprinted with a hash. Submitting the same text again reuses the saved version, and the
  AI is not called twice for the same resume + job description pair.
* **PDF text extraction:** PDFs only, up to 5 MB. Scanned (image-only), corrupt and
  password-protected PDFs are rejected with a clear message.
* **AI analysis (Google Gemini):** returns an overview, how well the resume matches, content
  that is irrelevant to the job, missing requirements, suggestions, and extra details
  (strengths and matched keywords). If one Gemini model fails or returns unusable output, the
  next model is tried. If all fail, the API answers `503` instead of crashing.
* **Safe with double clicks:** two requests at the same moment cannot create duplicate versions.
* **Question generator:** creates interview questions from your saved resume and job description
  (and the analysis, if there is one). Every question is saved, and every new round is told what
  already exists, so it never repeats itself. Exact repeats, re-spaced copies and reworded copies
  are all thrown away. Choose how many (1-20), the categories (technical, behavioral, situational,
  resume_based, hr) and the difficulty, or leave them out for a balanced mix.
* **Interactive docs:** Swagger UI at `/docs`.

## Tech stack

FastAPI, SQLAlchemy 2 + PostgreSQL (psycopg 3), Redis, Google GenAI SDK, PyMuPDF.

## Prerequisites

* Python 3.10+
* PostgreSQL (the supplied `db_structure.sql` was generated by PostgreSQL 18.6; on a server
  that does not support `transaction_timeout`, remove that `SET` line before importing it)
* Redis (used for logout)
* A Google Gemini API key

## Setup

**1. Create a virtual environment and install the packages**

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**2. Create the database and its tables**

```bash
createdb your_db_name
psql -d your_db_name -f db_structure.sql
```

**3. Create a file named `.env` next to `main.py`**

```
DATABASE_URL=postgresql+psycopg://username:password@localhost/your_db_name
SECRET_KEY=paste_a_long_random_string_here
GOOGLE_API_KEY=your_google_api_key_here
SPEECH_PROVIDER=browser

# optional when SPEECH_PROVIDER=azure
AZURE_SPEECH_KEY=
AZURE_SPEECH_REGION=
AZURE_SPEECH_LANGUAGE=en-US

# optional
REDIS_URL=redis://localhost:6379/0
ACCESS_TOKEN_EXPIRE_MINUTES=2880
COOKIE_SECURE=false
AUTO_CREATE_TABLES=false

# optional SMTP for email verification and password reset
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your_smtp_username
SMTP_PASSWORD=your_smtp_password
SMTP_FROM_EMAIL=no-reply@example.com
SMTP_USE_TLS=true

# optional Sentry error tracking
SENTRY_DSN=
SENTRY_ENVIRONMENT=production
SENTRY_TRACES_SAMPLE_RATE=0
```

Generate a secret key with `openssl rand -hex 32`. Never commit `.env` to git.

**4. Start Redis and the server**

```bash
sudo service redis-server start      # or: redis-server
uvicorn main:app --reload
```

**5. Try it**

Open <http://127.0.0.1:8000/docs>, then:

1. `POST /register` to create an account.
2. `POST /login`. This sets your login cookie.
3. `POST /analyze` with a PDF resume and a job description. Leave either one empty to reuse
   the latest one you saved (a new user must provide both).
4. `GET /questions/options` after login to see what you can ask for: the five categories
   (`technical`, `resume_based`, `behavioral`, `situational`, `hr`, each with a description and an
   example), the three difficulty levels (`easy`, `medium`, `hard`) and how many questions you can
   request (1 to 20).
5. `POST /questions/generate` to get new interview questions. You need to have used `/analyze`
   first. Call it again for more: each round gives questions you have not seen. Send
   `{"count": 5, "categories": ["technical"], "difficulty": "hard"}` to choose, or send
   `{"count": 10}` for a balanced mix.
6. `GET /questions` to see every question so far (filters: `category`, `batch_no`, `limit`, `offset`).
7. `POST /logout` when you are done.
8. Open <http://127.0.0.1:8000/interview> in Chrome or Edge for the browser voice mock
   interview. You must already be logged in in the same browser and have a saved resume and
   job description.
9. Open the **Coach assistant** section in the workspace to ask personalized questions about
   your resume, target role, generated questions, and interview history.

Health checks:

* `GET /health/live` confirms that the process is running.
* `GET /health/ready` checks PostgreSQL, Redis, and Gemini configuration. It returns `503`
  until all three are available.

Registration and login are required before using analysis, question generation/options,
interview sessions, account data, or account-management services. The public exceptions are
registration, login, logout, health checks, metrics, API documentation, email verification by
token, and password-reset requests/confirmation.

The authenticated coach assistant exposes:

```text
GET    /assistant/messages
POST   /assistant/messages
DELETE /assistant/messages
```

It uses the signed-in user's latest resume, job description, analysis, generated questions,
interview turns and summaries, and voice metrics. Conversation messages are stored per user and
are included in account export and deletion. The assistant is a preparation aid, not a certified
hiring or pronunciation assessment.

Every response includes an `X-Request-ID` header. Use it when correlating a client report with
server logs. Resume text, job descriptions, prompts, tokens, and passwords are not included in
request IDs.

## Responses to know about

| Status | Meaning |
|---|---|
| 400 | Missing input (for example a new user sent no resume), or the file is not a PDF |
| 401 | Not logged in, or the session ended |
| 413 | Resume bigger than 5 MB |
| 422 | The PDF has no readable text, is corrupt or password-protected, or the text is too long |
| 503 | The AI service is unavailable. Try again in a minute |

Asking for questions before any resume and job description are saved gives `400`. A `count` outside
1-20 gives `422`.

## Database setup and schema changes

There is currently no `migrations/` directory. `db_structure.sql` is the checked-in database
schema snapshot for a new database. By default, the application does not modify the schema on
startup. Set `AUTO_CREATE_TABLES=true` only for local development if missing tables should be
created automatically; it is not a replacement for a production migration system.

For a new local database:

```bash
createdb your_db_name
psql -d your_db_name -f db_structure.sql
```

For an existing database, verify that its schema matches `models.py` before starting the
application. In particular, the `questions` table and the `NOT NULL` constraints on
`users.password_hash`, `users.created_at`, and `resume_analysis.analysis_hash` are required.

## Tests

The tests use a fake Gemini, so they cost nothing and need no API key. They **empty the tables
they use**, so they only run against a database whose name ends in `_test`:

```bash
python -m pip install -r requirements-dev.txt
createdb your_db_name_test
psql -d your_db_name_test -f db_structure.sql
TEST_DATABASE_URL=postgresql+psycopg://username:password@localhost/your_db_name_test \
  python -m pytest -v
```

The tests are split across `test_fixes.py` and `test_questions.py`; the exact number of collected
tests can change when cases are added or parametrized.

Redis must be running for the logout test.
GitHub Actions runs the same suite with PostgreSQL and Redis services on every push and pull
request.

Each request also produces a server log entry containing its request ID, HTTP method, path,
status code, and duration. Request bodies and uploaded document contents are never logged.
Responses also include standard security headers that disable MIME sniffing, framing, referrer
leakage, and unused camera, microphone, location, and payment capabilities.

## Account security

Authenticated users can change their password with `POST /account/password/change`. Changing a
password invalidates existing sessions.

Email verification is available through `POST /account/verification-email` and
`POST /account/verify-email`. Password recovery uses
`POST /account/password/reset/request` followed by
`POST /account/password/reset/confirm?token=<token>`. SMTP must be configured for these email
flows. Reset responses do not reveal whether an email address exists.

Sentry is initialized only when `SENTRY_DSN` is set. Leave it empty to use structured logs
without an external error-tracking service.
Prometheus-compatible request counters and latency histograms are available at
`GET /metrics` for a metrics scraper.

For an existing database created before these account-security fields were added, apply:

```sql
ALTER TABLE users
  ADD COLUMN IF NOT EXISTS email_verified boolean DEFAULT false NOT NULL,
  ADD COLUMN IF NOT EXISTS email_verification_token_hash varchar(64),
  ADD COLUMN IF NOT EXISTS email_verification_expires_at timestamp,
  ADD COLUMN IF NOT EXISTS password_reset_token_hash varchar(64),
  ADD COLUMN IF NOT EXISTS password_reset_expires_at timestamp,
  ADD COLUMN IF NOT EXISTS password_changed_at timestamp;
```

## Voice mock interviews

Mock interviews are stored as four related records:

- `interview_sessions` captures the resume/JD version snapshot, duration, status, and lifecycle.
- `interview_turns` stores each spoken question and answer transcript.
- `interview_summaries` stores the final strengths, weaknesses, learning areas, and suggestions.
- `voice_analyses` stores per-answer fluency, grammar, pacing, filler-word, and clarity metrics.

The first implementation provides the session lifecycle:

```text
POST /interviews
POST /interviews/{id}/start
POST /interviews/{id}/finish
GET  /interviews
GET  /interviews/{id}
GET  /interviews/{id}/summary
DELETE /interviews/{id}
```

`POST /interviews` snapshots the latest saved resume and job-description versions. The browser
lets the user enter any whole duration from 1 to 60 minutes and converts it to the backend's
`duration_seconds` field. The backend allows only one preparing or active interview per user and
enforces a duration from 60 seconds to 3600 seconds. The live voice WebSocket, speech-to-text, adaptive interviewer, text-to-speech,
turn persistence, and final evaluation are implemented incrementally through the
authenticated WebSocket:

```text
WS /interviews/{id}/voice
```

The default `browser` provider uses the browser Web Speech API, so no Azure
subscription or payment card is needed. The browser speaks each `question.text`
with `speechSynthesis`, listens with `SpeechRecognition`, and sends:

```json
{"type":"answer_transcript","text":"The recognized answer"}
```

The server stores the completed turn, sends the next question, and closes the
stream when the configured interview duration expires. Azure remains available
as an optional provider by setting `SPEECH_PROVIDER=azure` and configuring its
credentials.

After each completed answer, the adaptive interviewer evaluates the response
against the snapshotted resume, job description, and prior interview turns.
It stores a validated score and feedback in `interview_turns`, then chooses the
next category, difficulty, skill focus, and question. If Gemini is unavailable
or returns invalid data, the session continues with the next saved question
instead of failing.

When an interview is completed, `GET /interviews/{id}/summary` returns the
persisted final assessment, including the overall score, strong and weak areas,
skills to learn, missing job requirements, feedback, and recommendations.

Browser voice mode also creates a `voice_analyses` record for every completed
answer. It derives speaking rate, filler words, repeated words, pacing, fluency,
and clarity from the transcript and server-measured answer timing. It also uses
the browser's speech-recognition confidence and microphone silence transitions
for an acoustic-confidence estimate and pause counts. Raw recordings are stored
temporarily for background pronunciation processing and removed after processing
or retention cleanup. Pronunciation scoring is unavailable immediately in browser
mode because the browser does not expose phonemes; `pronunciation_score` is
returned as `null` until the optional worker finishes.

Browser answers also send short-lived `MediaRecorder` audio chunks to a Redis
queue. The interview does not wait for this work: `python pronunciation_worker.py`
processes queued files and updates `voice_analyses.analysis_status` to
`processing`, `completed`, or `failed`. The default local provider uses
`facebook/wav2vec2-lv-60-espeak-cv-ft` and compares transcript phonemes with
phonemes detected from the audio. This is an approximate intelligibility score,
not a certified language assessment. The model is downloaded from Hugging Face
on the first processed answer. Temporary audio is removed after processing and
stale files are cleaned after `AUDIO_RETENTION_SECONDS` (default 900 seconds).

On Ubuntu, install the provider dependencies once:

```bash
sudo apt update
sudo apt install -y ffmpeg espeak-ng redis-server
source .venv/bin/activate
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
pip install transformers phonemizer
```

Set `PRONUNCIATION_PROVIDER=local_wav2vec2` in `.env`. Run both the API and
worker together with `bash run_interview.sh`; Redis itself must be running as a
system service.

Minimal browser client logic:

```javascript
const socket = new WebSocket(`/interviews/${sessionId}/voice`);
const SpeechRecognition =
  window.SpeechRecognition || window.webkitSpeechRecognition;

socket.onmessage = ({ data }) => {
  const message = JSON.parse(data);
  if (message.type !== "question") return;
  speechSynthesis.cancel();
  speechSynthesis.speak(new SpeechSynthesisUtterance(message.text));

  const recognition = new SpeechRecognition();
  recognition.lang = "en-US";
  recognition.onresult = (event) => {
    socket.send(JSON.stringify({
      type: "answer_transcript",
      text: event.results[0][0].transcript,
    }));
  };
  recognition.start();
};
```

The browser workspace is available at `/`. It presents registration and login
first, then exposes the authenticated resume/JD upload, analysis, question
generation, and mock-interview actions from one dashboard.

For an existing database, run `schema_upgrade.sql` before using the interview or assistant
endpoints. For a fresh database, use the updated `db_structure.sql`. Do not run the full schema
dump against a database that already contains data.

## Account deletion

An authenticated user can permanently delete their account and all saved resume versions, job
description versions, analyses, generated questions, and profile data:

```bash
curl -X DELETE http://localhost:8000/account \
  -H "Cookie: access_token=<token>"
```

The endpoint returns `204 No Content` and clears the browser session cookie. This operation is
irreversible.

Users can export their saved application data before deletion:

```bash
curl http://localhost:8000/account/export \
  -H "Cookie: access_token=<token>"
```

The export includes account metadata, resume and job-description versions, analyses, and
generated questions. Password hashes and authentication tokens are never included.

## Current limitations and operational concerns

* `COOKIE_SECURE` defaults to `false` for local HTTP development. Set `COOKIE_SECURE=true` when
  serving the API over HTTPS; otherwise browsers will not send the login cookie.
* Redis is required for token revocation. If it is unavailable, authenticated requests and
  logout return `503` rather than allowing a token whose revocation state cannot be checked.
  Redis errors are logged.
* There are no rate limits or per-user AI quotas. Each analysis can call Gemini, and each
  question-generation request can call Gemini multiple times because model fallback is enabled.
* Concurrent resume, job-description, and analysis writes retry database uniqueness conflicts,
  but concurrent identical analysis requests can still call Gemini more than once before one
  result is saved.
* Question generation uses a PostgreSQL transaction advisory lock per user and a unique
  `(user_id, batch_no, item_no)` constraint to protect concurrent batch allocation. This
  serializes question generation requests for the same user.
* Uploaded PDFs are held in memory only for the duration of the request. PyMuPDF extracts the
  text directly from the upload bytes, and the original PDF is not written to local storage.
* Schema changes are not managed by migrations. Do not rely on application startup to perform
  production database upgrades.
* There is no email verification, password reset, account deletion, data-retention policy,
  health endpoint, rate-limit endpoint, deployment manifest, or CI workflow.
